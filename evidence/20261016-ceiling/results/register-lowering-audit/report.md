# Register hint accounting correction

CPU-only disassembly distinguishes three implementations. The vendor native FC1 CUBIN has REG128 and eight `USETMAXREG` instructions. The inspected Prims TS M64/M128 and complete resident CUBINs have REG30–32 and no `U?SETMAXN?REG` instructions, despite PTX containing48/160 hints. The audit includes every CUBIN hash, SASS, resource header, highest architectural R index and ELF reconfiguration-field presence in result.json. `SETMAXNREG` alone is an insufficient SASS search because Blackwell uses the name `USETMAXREG` for the vendor kernel.

Therefore53,248 versus32,768 is only a sum of source-role hints. It does not establish actual allocation or an M64-one-CTA/M128-two-CTA occupancy transition. Earlier wording suggesting that implication is withdrawn; original frozen protocols and numeric results remain unchanged. M128 still changes actual thread count512→384, MMA decomposition and output coordinates. Relative to the vendor, the prototype also changes pipeline staging and launch/resource policy, which must be separated before attributing a gain.

[NVIDIA PTX documents setmaxnreg](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html#miscellaneous-instructions-setmaxnreg) as a per-CTA register-pool operation whose effect depends on suitable kernel compilation/launch settings. This supports checking final machine code and launch resources; it does not prove a performance result. No new register-cap sweep is warranted by the old source-budget argument. Numerical checks and the full-body performance gates remain intact.

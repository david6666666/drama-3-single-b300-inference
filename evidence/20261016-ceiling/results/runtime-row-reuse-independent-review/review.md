# Mixed row reuse runtime: independent CPU review

No source blocker found in the reviewed five files. Fifteen independent naive-prefix cases (five deployed shape buckets × identical/suffix-changed/reversed prompts) exactly reproduce the canonical row map, retain every decode/original padding owner, keep inverse indices below the unique-row count and reject same-length changes through a NumPy view. CUDA remained uninitialized. Reviewed file hashes are in result.json; these are uncommitted candidate sources, not a GPU-qualified release.

The prefix comparison includes all eleven integer columns through each row. Earlier-owner references are canonicalized when assigned, so a longest-prefix match cannot create an alias chain. Decode and original padding rows are never merged. Compact capacity fillers duplicate row0 but are not referenced by any full-row inverse index; they introduce no new real state row. They can change GEMM routing/padding work and must still pass all original numerical gates.

MixedGraph.forward first loads requests, updates full row metadata and resets fresh prompt state, then gathers compact slots once. All stateful attention/GDN and the teacher tower remain full-row operations. Only stateless MoE input/output paths use the compact map. New teacher next-row labels are not used as a reason to merge teacher rows. prepare binds the plan to exact CPU prompt bytes, avoiding inference-tensor mutation-version assumptions.

Persistent row_indices and compact_slots are allocated outside capture and retained by each graph object. The per-layer index_select result is retained as moe_parts' x through projection, routing and shared-expert submission. Mixed execution rejects an auxiliary shared-expert stream; all those allocations and launches follow the same stream. Pending routed/shared/gate tensors, including the gate view's base storage, remain live through the next layer's inverse combine. The new inverse norm returns a full-sized output while updating the original full residual. This preserves the ordinary single-stream capture lifetime pattern; it does not reuse one externally overwritten scratch tensor across forty layers.

MixedGraph.run clones both graph outputs before a later same-pool graph replay. The engine passes only freshly built plans and selects a graph keyed by full decode/prefill/span/compact shape. Unsupported/no-fitting shapes fall back to the original graph. Source guards require mixed backbone/span256/fused residual and the existing FlashInfer mixed path. The default-off branch does not enter compact logic.

Required hardware validation remains broader than the earlier externally retained40-buffer artifact: exercise every compact K/F bucket, changed/reversed conditioning, partial decode, reused slots and changing owner maps; alternate original→compact→different compact→original graphs in the actual shared pool; verify both returned clones after subsequent replays and all participating/nonparticipating state/RNG. Include first/last row and missing-prompt/padding boundaries. CPU source reasoning is not a replacement for that gate.

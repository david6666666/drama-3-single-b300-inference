# FC1 full-tile scale cache: CPU preparation only

The artifact compiles and the CPU address/bit-copy proof passes. No GPU execution, numerical acceptance, latency measurement or runtime promotion has occurred. Original metadata-ready and route-cache failures remain unchanged.

The sole device change stages the original FP32 FC1 scales once per active work tile: sixteen groups of eight activation scales and one expert/output-block weight scale, 144 floats or 576 bytes. The original B activation gather4 TMA, weight TMA, K32 MMA/K128 accumulation, scale consumer arithmetic, FP8 boundaries and native activation/finalizer are retained. Metadata-ready FC2 is byte-identical at CUBIN level. Artifact-local compiler class/pipeline overrides are restored in `finally`; installed libraries and production runtime are untouched.

`cpu-check.json` records 1,113,949 CPU assertions over 41,753 tile/output-block transactions: all fifteen archived native fixtures, their original and a second legal within-tile row permutation, all eight FC1 output scale blocks, all sixteen K groups, synthetic valid counts 0–8, poison inactive routes, signed zeros/NaN payload bit patterns, ten unsupported-config negative cases and the actual precompile IO shape guard. CUDA stayed uninitialized. These are address and copy simulations, not execution of candidate machine code. The inherited full fifteen-fixture logical boundary, reused-graph, metadata ownership, guard, RNG and empty GPU gate remains required.

Actual CPU AOT resource accounting is 73,144 dynamic + 2,048 static = **75,192 bytes per FC1 CTA**, precisely 576 bytes above the prior candidate. The CUBIN header reports REG32 and no stack/local/spill. FC2 stays 74,664 bytes. FC1 CUBIN is `311a2b1d147155ecebbad21e522cfeeba3c75ebe4b30ada8bb5eca98308d8d33`; FC2 is the unchanged `ea52321ec64fc9976a306b7c7aeeb0805033c2e024034e5cc6ce266e7d95b170`.

`compile-audit.json` contains 33 checks. All seven statically unrolled SF work bodies now contain LDS/STS, no global load or cp.async, and the shared-proxy fence. SASS drops fourteen LDGSTS and seven LDGSTS-barrier instructions from the old SF path; it uses generic-store publication (`MEMBAR.ALL.CTA`, `FENCE.VIEW.ASYNC.S`, ordinary `SYNCS.ARRIVE`). Weight-TMA, activation gather4, MMA and PDL instruction counts remain unchanged. Equal opcode counts do not prove equal scheduling or performance.

The full-cache producer uses one warp. `bar.warp.sync -1` appears after its preload stores in PTX. At the corresponding SASS location 0x3940 the compiler emits NOP; the preceding stores 0x38f0–0x3930 are reconverged before a uniform stage loop. This must not be reported as an emitted WARPSYNC at that point. The source/PTX synchronization contract and hardware exact gate, rather than an invented SASS instruction, are the relevant evidence. Only this producer reads the full cache. Consumer warps read the original circular stage after native acquire/release, so preparing the next tile cannot overwrite a still-live consumer input.

The scale task retains its native PDL wait before prepare and refreshes every tile's token/expert/absolute-limit metadata. Inactive rows do not dereference routes. The AsyncThread producer has the same 32 participating lanes; ordinary STS publication does not reuse a cp.async-only arrival. The four-stage SF allocation, consumer layout and dequant arithmetic remain native.

New checker scripts pass Ruff. The compiled helper was kept byte-identical after AOT; its three style-only diagnostics (I001, PLR0402, UP045) match the surrounding native DSL import/annotation style and are explicitly excluded for that file. No ignored correctness diagnostic or test failure is represented as a pass.

This candidate changes dependency placement, not scale or weight payload size. It also adds shared copies and front-loads scale gathering. A complete native-call gain is unproven. Any later hardware experiment must freeze sources and run the original exact gate first, stop on the first failure, and require each of the three real complete-call cases to improve by at least 5% in the initial screen before repeated timing. Native baseline PDL remains enabled.

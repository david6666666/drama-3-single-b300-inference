# FC1 full-tile SF cache independent CPU review

No source blocker identified for the fixed candidate, and no GPU work was performed by this review. This is not a numerical PASS or a performance claim. Reviewed file hashes and a separate nine-count address enumeration are in the companion JSON.

The cache contains 144 original FP32 values: sixteen K128 blocks × (eight activation scales plus one weight scale). The 32-lane producer maps `lane%8` to token and `lane//8 + iteration*4` to K block. Across four iterations, all128 activation entries have one owner. Lanes0–15 each store one weight scalar in column8; the two write sets are disjoint and cover every cache cell. Enumerating valid_rows0..8 confirms exactly16×valid_rows activation-scale reads and no invalid-row global load. Weight offsets preserve native expert/output-tile/K order.

Only this producer warp reads the full cache. The consumer epilogue continues to read the original per-K circular stage. Each stage is acquired before producer STS and released through the paired AsyncThread pipeline; the next tile may reuse the full cache after the producer has copied all its K slices, without waiting for consumers of those copied stages. No cross-CTA sharing or new consumer pointer is introduced. The original persistent work loop, skip/drain path and task PDL wait before prepare remain present.

The pipeline override changes only smem_dsfp8_sfab, preserving stage count, one32-lane producer and the original epilogue consumer count for cluster1. Plain STS is published with the AsyncThread arrival rather than the original cp.async completion mechanism. The exact fixed IO assertion K2048 establishes sixteen K blocks, and the config assertions fix N8/one SF warp/routed FC1. This adapter must not be used for another geometry without a new contract.

PTX contains bar.warp.sync after cache stores. The compiler lowers that site to NOP at SASS0x3940, following predicated stores; this review therefore does not claim an explicit WARPSYNC instruction at the cache publication site. It relies on the compiler's lowering of the valid PTX contract and still requires the declared hardware exact gate. The K-loop uses LDS/STS with MEMBAR.ALL.CTA, FENCE.VIEW.ASYNC.S and AsyncThread arrival. There is no SF LDGSTS/cp.async left in that loop. Native consumer dequant/FMA and all original quantization boundaries are inherited unchanged.

The compile patch is installed only around the FC1 compile in a try/finally and restores both resource and pipeline factory before compiling FC2. The recorded FC2 binary is unchanged. FC1's actual compiled shared footprint is75192bytes, 576bytes above its parent; baseREG32 and zero spill are recorded. PTX register hints must not be treated as executed SETMAXNREG or residency proof.

This can remove dependent per-K scale global supply while preserving original scale bits; it still has per-K stage barriers and an added LDS/STS path. The current source/counters do not establish that the removed supply dominates complete MoE time. The original15 exact/live-map/reused-graph and whole-empty lifecycle gates must precede a complete-call native comparison. No branch reduction, new quantization, kernel-only gain or PC-stall causal claim is justified by this review.

# Native two-frame overlap: independent dependency review

The checkpoint permits a real dependency split after the first residual codebook head. This does not omit model work or predict a draft frame. The next backbone can run while the preceding tower produces the remaining eight residual codebooks; the next tower must join that work first. Any speedup remains unproven until a fixed-work, exact-state fork/join test.

The indexing matters: `tower.py:289–306` defines `embedding_sum(first,end)` over `frames[:,1+first:1+end]`. With `vq_backbone_codebooks=1`, backbone consumes the main token and codebook 1 in **frames[:,2]**, not semantic codebook 0 in frames[:,1]. `model.py:698–713` produces that codebook after residual layer index 0 and sample stream 2. The remaining residual layers produce codebooks 2–9. The next shared tower needs those complete previous-frame codebooks through `embedding_sum(frames,2,10)` at `model.py:681–682`.

Review findings, against frozen source-rich-timeline ab6da532083854670348583d9ec9f2a16d184dfb:

- **Separate attention metadata and workspaces.** `AttentionBatch` owns its 128 MiB workspace, page indices and lengths (`model.py:76–105,139–140`). Tower frame t reads position p while backbone frame t+1 reads p+1. Reusing one batch or mutating its positions/refresh buffers while the old tower runs is a race. Use separate batch objects and position tensors; immutable slot order can be shared only for the entire two-frame operation.
- **Preserve sampler order.** `tower_forward` increments one model-wide scalar at line 671. Every residual sampling kernel reads that scalar at execution (`kernels.py:496–497`) and derives randomness from step, row and stream. Start only backbone t+1 early. Incrementing/sampling tower t+1 before residual tower t joins changes the old frame's samples. Row order must remain fixed. Snapshot/compare the scalar and all request history, not only final codes.
- **KV and recurrent storage are separable by layer.** Backbone indices are 0–39; tower attention uses 40+index (`model.py:322,634–646`). The main recurrent states are only updated by backbone (`model.py:402–405`). Thus disjoint-layer writes are safe in principle, provided backbone t+1 starts after backbone t and tower t+1 starts after tower t; never execute two backbone frames for the same slot concurrently.
- **Preserve temporaries and graph pool ownership.** Backbone next-hidden, tower current-hidden, partial/full frame buffers, sampling temporaries and attention workspaces must remain live across fork/join. Separate captured graph pools are the simplest initial control; sharing a pool whose previous invariant was serial replay is unsafe. Capture BLAS workspaces on the actual participating streams and retain stream/context owners. No mid-flight replay may overwrite a graph output before its consumer finishes.
- **Declare the serial reference for EOS/max_frames.** Two ordinary single-step graphs reload through `DeviceRequests._load`; `_save` appends only if old done=0, main!=EOS and count<limit (`runtime_state.py:24–43`). To match this reference, the private next-prefix/position/history must use that *append* mask, not next-done: a last allowed frame still becomes the next input even though it sets done. In contrast, existing `DecodeGraph(steps=2)` unconditionally uses the just-produced frame, shifts local history and increments local positions even after EOS (`engine.py:116–125`). These are distinct existing padded/finished-row semantics; do not silently compare one against the other.
- **Do not release/admit/emit halfway through the pair.** Requests, slot generations, active row order and cancellation ownership must remain fixed until both streams join. `_save` must not publish code/frame counts before the complete frame exists. Codec gather cannot see a partial row. `complete_decode` consumes each frame until first EOS/max_frames and frees once (`engine.py:582–609`). A service implementation must also honor next audio emission boundaries and pending admission; existing multi-step scheduling checks these at lines 529–540. A fixed-work microbench does not establish service scheduling safety.
- **Treat overlap as a measured budget, not a free saving.** Tower and backbone share HBM/L2/SMs; the green-codec experiment demonstrated that concurrency changes stage duration. Require serial two-frame versus overlapped two-frame total makespan, each branch completion, all native outputs/state/RNG, and a GPU timeline establishing real overlap. Later service evaluation must include admission delay, TTFA and codec queues.

Recommended first gate: unchanged roster and explicit two-single-step reference; B64 plus a partial padded batch; EOS and max-frame edge cases; exact real and nonparticipating state, RNG and frames; no auxiliary sampling before old tower completion. Keep initial artifact opt-in and production source unchanged until these gates and a material fixed-work benefit pass.
